# 🎙️ Meeting Notes：逐字稿 → 可用的會議紀錄

> 逐字稿是原料，不是成品。目標：主人三個月後打開這份檔，30 秒內知道「發生什麼、定了什麼、我要做什麼、當時誰說了哪句關鍵的話」。
> **鐵律：寧可漏改，不可錯改。** 整理可以主動，校正必須保守。

---

## 輸入

- **貼上逐字稿**（最常見）：直接開工。
- **給音檔路徑**：先問主人「你用什麼工具轉逐字稿？」。不要替主人選工具、不要假設他裝了什麼。他轉好貼回來再繼續。
- **只有口述大意、沒有逐字稿**：照做第 3 步以後，但在檔頭標明「無逐字稿，依口述整理」，不編造引言。

開工前先問缺的 metadata（一次問完，別一題一題）：日期、與會者、場合、關聯專案。逐字稿或行事曆看得出來的就不要問。

---

## 流程

### 0. 準備

1. 跑 `date`，確認今天日期（會議日期若不同，以會議日期為準，並問清楚）。
2. 讀 `TOOLS.md` 找：**知識庫路徑**、**會議 Hub 位置**、**個人詞庫路徑**。讀 `USER.md` 認識主人與常見人名。
   - 知識庫路徑沒寫 → 問主人一次，立刻記進 `TOOLS.md`。
   - 個人詞庫沒寫 → 在知識庫建 `_維運/詞庫.md`，路徑記進 `TOOLS.md`，並告訴主人「我建了詞庫，之後每次校正都會自動長」。

### 1. 清洗

- 去掉贅詞堆疊（嗯、那個、就是）、重複斷句、轉錄工具的時間碼雜訊，保留語意與語序。
- 轉錄常見幻覺要清：結尾重複短語、連續重複同一字、字幕署名之類憑空多出的句子。
- 簡繁混雜時統一成台灣繁體與慣用語。
- 保留一份 raw 原檔（或原文放在筆記最後的 `<details>`），整理稿錯了還能回頭查。

### 2. 小心校正

只修**明顯的聽寫錯字**（同音字、被轉錯的專有名詞）。**不改原意、不潤飾語氣、不把口語寫成書面語。**

1. 先套**個人詞庫**（格式：`誤聽 → 正確`，一行一組）。
2. 其餘不確定的字，**依序查證，查不到才標 ⚠️**：
   ① 同場其他地方是否出現過正確寫法／行事曆事件標題／議程，② 知識庫裡有沒有這個名字（搜尋），③ 公開資訊（只查公開的，不把會議內容當關鍵字送出去）。
   ⚠️ 的意思是「我查過了還是不知道」，不是「我懶得查」。標法：`⚠️[原文?]`，並在回報列出「我用 ①②③ 查無」。
3. **數字、金額、日期、百分比：絕不靜默改**。可疑就標 ⚠️ 請主人確認。
4. 錯誤密度超過約兩成（大半句子都聽不準）→ 不逐字追，改產「重組成段落＋重點」的版本，並保留 raw。
5. 同一個專名不要拿知識庫舊筆記互相佐證（舊檔可能是同一個錯字），要溯到更硬的來源（官網、合約、信件、對方自己寫的字）。

### 3. 整理

固定產出這幾塊（每塊沒有就寫「本場無」，不要省略標題）：

- **一段摘要**（3–5 句：為什麼開這場會、最後走到哪）
- **決議**：拍板了什麼（誰決定、前提是什麼）
- **待辦**：`誰 / 做什麼 / 何時`。期限沒講就寫「未定」，不要替人編。
- **待答問題**：懸而未決的
- **誰說了重要的話**：照逐字稿**原文**引用，標時間戳與說話者，引句前後不改字。轉述放在引句外面。

### 4. 深度洞察（每場至少 2–3 條，要有錨點）

洞察不是摘要的換句話說。是「記錄裡沒寫、但回頭看才看見」的東西。從這些切面挑有料的：

1. **最好的部分**：全場最有價值的一段，是什麼、為什麼（給理由，不給形容詞）。優先找沒被設計卻自己發生的那段。
2. **跨場比較**：跟知識庫裡最近 2–3 場同類會議比，立場、口徑、進度有什麼變化？同一個數字或說法前後不一致就列出。
3. **未來會回頭咬的一句話**：某個人描述自己的處境，而那個處境結構上也會輪到主人。
4. **對主人本人的觀察**：他在這場的反應模式（只陳述，不勸告、不排時程）。
5. **我自己的盲點**：這場我標錯或漏看了什麼。沒有就寫「自捕 0，這通常代表我沒在找」。
6. **這場埋下的種子**：新的關係、可獨立成文的段落、可搬進既有流程的方法。只 surface，不代為決定。

**驗收句**：這裡面有沒有至少一條是「主人自己在場也沒看見的」？全是他已經知道的 = 只做了記錄，重寫。
**每條洞察要能被指著問「你從哪看到的」**：附時間戳或原句。答不出來就刪。

### 5. 歸檔

1. **放哪**：會議 Hub 資料夾。**先讀該資料夾的維運規則檔**，照它的規則放。沒有維運規則檔就問主人，並建議補一份。
2. **檔名**：`YYYY-MM-DD - 會議 - 主題`（例：`2026-03-14 - 會議 - 與設計師的週會`）。
3. **frontmatter**：`type: meeting`、`date`、`participants`、`project`、`tags`。
4. **連結**：至少一個連回會議 Hub，與會者的人物頁、關聯的專案頁**存在才連**。不存在的不要偷建，列在回報裡問主人「要不要建」。
5. 回到 Hub 補一行索引（若 Hub 的維運規則要求）。

### 6. 回寫

- **人物頁**：加一行「YYYY-MM-DD 會議：當時的立場／承諾／新資訊」，連回本檔。
- **專案頁**：更新進度、新決議、新待辦、下一個里程碑。與舊內容衝突時，**兩邊並列標日期，不覆蓋**。
- 只寫會議裡真的有的事。會議沒講的近況，不要順手補。

### 7. 日誌

照 `CLAUDE.md` 的即時日誌鐵律，在 `memory/YYYY-MM-DD.md` 追加一段：做了什麼（哪場會議、歸檔到哪）、回寫了哪些頁、詞庫新增幾條、還在等主人確認什麼。

### 8. 詞庫自我成長

本場主人確認過的錯字對照（含你高信心且有硬來源的）→ 追加進個人詞庫，回報時列出「本場新增 N 條」。
入庫前造一句測試句（錯字加常見前後綴），確認不會誤傷正常詞。模糊的（可能是正常詞）不要入庫。

## 回報格式

簡短列：檔案位置、⚠️ 待確認清單（含查證到第幾階）、新增詞庫條數、建議新建的人物／專案頁、要不要把待辦推進你的待辦工具（**不自動建，先問**）。

## 邊界

- 對外分享的版本（要給與會者或公開的）另開一份，拿掉洞察與對第三方的私下觀察。
- 會議裡的敏感內容，在主人自己的私人知識庫裡完整記錄，不美化也不略過，但不替他轉寄、不外送。
- 沒有主人授權，不建立人物頁、不推待辦、不對外寄任何東西。

## 怎麼讓這個技能越用越好

每次用完問主人一句：「這次哪裡不好用？」把答案寫回本檔（調整步驟、補規則），版本號 +0.0.1（1.0.0 → 1.0.1）。詞庫會自己長，流程本身靠這一句話長。
