# 📝 Daily Log：邊做邊記

> 做了不記，等於沒做。記了不存，等於沒記。
> **收官是狀態，不是動作**：不要等到最後才說「收官」。每做完一件事，當下就記好、存好，session 在任何一刻結束都不欠帳。

---

## 什麼時候寫

每完成一個「節點」就寫一段，不累積：

- 完成一個子任務（或分身交件）
- 一次 commit、一次部署、一次對外送出（寄信、發文）
- 做了一個決定、聽到主人一句重要的話、被主人糾正
- 研究或討論告一段落

**判準**：如果現在 session 被關掉，主人會不會少知道任何一件事？會，就還欠一段日誌。

---

## 節點收官：每個節點同一手做完四件

1. **日誌**：在 `memory/YYYY-MM-DD.md` 追加一段（格式見下）
2. **存檔**：`git commit` 這次改的檔（有遠端就 push）
3. **知識**：值得留下的內容放進知識庫對應的位置（不是只留在日誌裡）
4. **教訓**：新學到的，先寫進 `memory/LESSONS-INBOX.md`，之後再消化進靈魂檔

回報給主人時，最後一行附收據，讓主人一眼知道有沒有記：

```
📝 日誌 HH:MM ⟨線名⟩（memory/YYYY-MM-DD.md）・commit a1b2c3d
```

---

## 日誌格式

一個檔＝一天，一段＝一件事的一次推進。主人只看 `grep '^## '` 就要知道：今天做了哪幾件事、各屬於哪條線、到哪了。

```markdown
## HH:MM ⟨線名⟩ 動詞開頭的事件（一句話說做了什麼）
- 📥 主人說：「原話」                ← 主人這次下了指令才寫
### 做了什麼
- 動作與判斷，一條一行
### 驗證
- 怎麼確認的：跑了什麼、看到什麼數字；沒驗就寫「沒驗」
### 坑
- 踩到什麼、為什麼、下次怎麼避開
### 交付
- 檔案路徑、commit、網址、知識庫筆記
### 下一步
- 沒做完的、卡住的、要誰決定的
```

### 規則

1. **時間是寫下這段的那一刻**，用 `date` 取，不憑感覺，不寫「下午」或 `14:xx`。最省事的寫法是用 `tools/log.sh`，時間由它自己取。
2. **線名**＝這件事屬於哪條工作線，例：`⟨官網線⟩`、`⟨報稅線⟩`、`⟨婚禮致詞線⟩`。同一條線跨天沿用同一個名字。
3. **只有三層**：`#` 檔頭、`##` 事件、`###` 子標，不用 `####`。
4. **五個子標固定**：做了什麼／驗證／坑／交付／下一步。沒有內容就省略那一個，不要自己發明新的子標。
5. **同一件事延續 → 開新段**，標題後面加「（續）」，線名一樣。不要回頭塞進舊段：中間可能已經有別的事，塞回去會讓時間軸說謊。
6. **只追加，不覆寫**。同一天的日誌可能有好幾個 session 一起在寫。要改舊段就精準改那幾行，絕不整檔重寫。
7. **跨日接續**：新的一天開新檔，第一段寫「承上：YYYY-MM-DD § HH:MM 事件」。
8. **一律用日期命名**。不要開 `project_xxx.md`、`feedback_xxx.md` 這種主題檔。主題的家在知識庫的 Hub，日誌只照日期走。

### 範例

```markdown
## 14:32 ⟨官網線⟩ 首頁改版上線
- 📥 主人說：「首頁先上，作品頁下週再說」
### 做了什麼
- 首頁換新版型，三張主圖重新壓縮
### 驗證
- 手機與電腦各開一次，圖片都在 1 秒內載入
### 交付
- commit a1b2c3d、https://example.com
### 下一步
- 作品頁下週改，等主人挑照片

## 16:05 ⟨官網線⟩ 首頁改版上線（續）
### 坑
- 舊網址 /works 沒有轉址，搜尋引擎會掉流量 → 補了轉址規則
```

## 用工具寫（推薦）

```bash
bash tools/log.sh '⟨官網線⟩ 首頁改版上線' <<'EOF'
- 📥 主人說：「首頁先上，作品頁下週再說」
### 做了什麼
- 首頁換新版型
EOF
```

標題不是 `⟨線名⟩ 事件` 的形狀，它會擋下來。檔案不存在會自己建好檔頭，只會追加到檔尾。

---

## 跟收官技能的分工

- **daily-log（本技能）**：邊做邊記，主力。每個節點當下做完。
- **after-action**：一段工作結束時跑，只剩「補漏＋萃取教訓＋整理」。因為記錄早就寫好了，它不是重建一整天的大工程。

---

## 怎麼讓這個技能越用越好

主人說「看不懂」「太長」「找不到」時，問一句：「是哪一段讓你看不懂？」把答案改進本檔的規則或範例，版本號 +0.0.1，下方記一行。
