# 戰場盤點：一次一件，陪你推完

> 清單長，是因為腦袋在當清單。我的工作是把它搬出來、分好、一件一件陪你做完。
> 一則訊息只端一件。你回了，我才動手下一件。

---
## 觸發

- 「戰場盤點」「分析手邊事情」「盤點待辦」「陪我把事情做完」「我事情好多」
- "triage my tasks"，或主人丟來一串事情、說「不知道從哪開始」

## 開場前的三個設定（只在第一次問）

1. **今天幾號**：先跑 `date`，日期不靠直覺。
2. **待辦清單住哪**：讀 `TOOLS.md`。裡面沒寫主人用哪個待辦工具，就問一次「你平常把待辦記在哪？」
   記下答案寫進 `TOOLS.md`。沒有任何工具就在知識庫開一份 `待辦清單.md` 當清單檔，也記進 `TOOLS.md`。
3. **知識庫路徑**：讀 `TOOLS.md` 或 `USER.md`。沒寫就問一次並記下，之後不再問。

## 流程

### Step 1：取得清單
三種來源擇一或混用：主人口述、主人貼上、從他的待辦工具或知識庫專案檔讀。
讀專案檔時看每個專案最上面的 frontmatter（狀態、下一步、截止日、球在誰）。
口述的零碎事先整理成逐條，念回去讓他確認有沒有漏。

### Step 2：先讀日誌，找出其實已經做完的
讀最近 3 到 7 天的 `memory/YYYY-MM-DD.md`，逐條對照清單：

- 日誌明確寫了做完 → 直接標完成，不用問。
- 看起來做了一半或可能做完 → 彙整成一題問：「這幾件我猜已經好了，對嗎？」附上日誌依據。
- 清單裡沒有、日誌卻有懸著的事 → 補進清單。

### Step 3：標給 AI 的事，直接做掉
主人標了「給 AI」、或明顯是查資料／整理／草稿／比對這類我能獨立完成的事，現在就做（可派分身並行）。
做完回報：做了什麼、產出在哪、有什麼需要他點頭。需要對外送出、花錢、不可逆的，只備好草稿，等他按。

### Step 4：主人的事，先在我這邊跑三道分析
主人還沒看到任何東西，這三道在我這邊先跑完：

1. **分群**：依主題歸成 3 到 6 群（例如一個專案、一個生活面向）。
2. **優先度**：每個主題給一個 P 值（P1 最高到 P4），一句話說理由：卡住別人嗎？有死線嗎？拖著會變貴嗎？
3. **四象限**：每一件放進「緊急且重要／重要不緊急／緊急不重要／都不」。

### Step 5：用一張精練清單對一次通盤認知
這是整個流程裡唯一一次給他看全貌。規格：

- 主題一行（含 P 值），象限逐件一行，**全部 ≤25 行**。
- 已完成的折成一行帶過，不展開。
- 最後一行寫我建議的開工順序。

虛構範例：

```
通盤（今天 10/12，共 9 件，已完成 2 件折疊）
P1 工作室搬家　　（房東月底前要答覆）
  🔴 緊急×重要　簽新租約（球在你）
  🔴 緊急×重要　叫搬家公司報價（我可備好比價表）
  🟡 重要不緊急　通知郵局與銀行改地址
P2 季度報稅　　（15 號截止）
  🔴 緊急×重要　整理 Q3 發票（我可先掃出缺漏）
  🟡 重要不緊急　確認可扣除項目
P3 朋友婚禮致詞　（下月才用）
  🟡 重要不緊急　想三個故事（我先出草稿，你挑）
P4 雜項
  ⚪ 都不　　　　整理舊檔案（建議放掉）
建議順序：簽租約 → 報稅發票 → 搬家報價 → 其餘
```

問他一句：「這個全貌對嗎？有漏的、放錯的跟我說。」他確認後才進下一步。

### Step 6：一則訊息只端一件
每則訊息固定長這樣：

```
【第 N 件／共 M 件】主題：事情名稱
我這邊備好了：（已經做掉或備好的東西，附位置）
你只要做：（一個動作，或一題）
我的建議答案：（讓他回「好」就能走）
```
規則：
- 一次只問一題，附建議答案。他回「好」「照你說的」就當同意。
- 等他回這一件，才動手下一件。不預跑、不一次丟三題。
- 他說「都做」「你排就好」→ 照清單順序往下做，每做完一件回報一行，最後回報完成順序。
- 不出「你要放掉哪一件」這種逼選擇的題。建議放掉的，我寫理由，他說不放就不放。

### Step 7：他猶豫時，出決策卡
訊號：「不確定要不要」「還在想」「好像都可以」。先停下來，不要硬推進度。

**第一段：直覺問卷（選擇題，一題一題問）**
1. 想要：如果它現在就做完了，你會開心嗎？（很開心／無感／鬆一口氣）
2. 想做：想到要動手，身體的反應是？（興奮／中性／抗拒）
3. 意義：做完之後，跟你在意的事有關嗎？（很有／有一點／沒有）
4. 消失：如果這件事明天憑空消失，你的第一反應？（可惜／無所謂／太好了）

每題 0 到 3 分，總分 0 到 12。**9 到 12 分**直接排進去，**4 到 8 分**是灰區（接第二段），
**0 到 3 偏向放下**（我寫一句溫柔的收尾理由，由他決定）。
**第二段：灰區才做**
- SWOT：做這件事的優勢、弱點、機會、威脅，各一兩行。
- 推翻成本：做了之後想反悔，要花多少力氣？
- 以終為始：三個月後希望看到什麼？這件事離那個畫面近嗎？
- 擔心的假設：你在擔心什麼？那個擔心有證據嗎？

**依猶豫種類加一把尺（擇一）**
- 「好像可以，但沒很想」→ Hell Yeah or No：不是「超想做」就先不做
- 「怕做了會後悔」→ 事前驗屍：假設半年後失敗了，最可能的三個原因
- 「怕得不敢動」→ 恐懼設定：把最壞情況寫具體，再寫怎麼補救
- 「短期痛、長期好？」→ 10/10/10：十分鐘後、十個月後、十年後怎麼看

決策卡最後給一個建議（做／排後面／放下）和理由，**他說了算**。

### Step 8：狀態寫回
每推完一件，當下就寫，不要攢到最後：

1. **專案檔 frontmatter**：更新 `status`、`next`（下一步）、`due`（截止日）、`ball`（球在誰）。
   只改這幾欄，不動正文。
2. **日誌**：先跑 `date`，在 `memory/YYYY-MM-DD.md` 追加一段，格式：

```
## HH:MM 戰場盤點：事情名稱
- 做了什麼：
- 決定：（含決策卡結論）
- 下一步／球在誰：
```

3. 待辦工具或清單檔：把完成的標掉。

## 收尾

全部走完（或他說今天到這）時回報：

- 完成幾件、依什麼順序，還懸著的事，各自球在誰、下一步是什麼。
- 最後問一句：「這次哪裡卡？」（見下一節）。

## 注意

- 全貌只給一次（Step 5），之後永遠一次一件。
- 日期、截止日來自 `date` 與他的檔案。對外送出、花錢、刪除等不可逆的事，等他明確說好。
---
## 怎麼讓這個技能越用越好

每次盤完，問主人一句：**「這次哪裡卡？」**（太囉嗦、分類不準、問題太多、順序怪都算）

1. 把答案寫進 `memory/LESSONS-INBOX.md`，一行：日期＋卡在哪＋怎麼改。
2. 如果是這個技能本身的流程問題，直接改本檔對應的 Step，在下方更新紀錄加一行。
3. 版本號 +0.0.1（例如 1.0.0 → 1.0.1），frontmatter 的 `version` 一起改。
4. 改完告訴主人改了哪一段、怎麼還原（git 看得到）。
