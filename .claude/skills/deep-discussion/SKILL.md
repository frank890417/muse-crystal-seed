# 🎙️ Deep Discussion — 訪談式深度討論

> 對話本身會讓主人的想法結晶。你的價值在提問。
>
> 主人的要求（一句話版）：「用訪談的方式跟我完整地討論這件事，並且同時把東西歸檔到知識庫。每訪談一輪就歸檔一次，讓知識庫的結構清晰有階層。把我當成最重要的受訪者，用提問挖出我心裡的想法。」

## 跟 after-action 的分工

| 技能 | 用途 |
|---|---|
| **deep-discussion**（本技能） | 對象是主人活的腦袋：即時訪談 + 邊談邊歸檔，產出是他的思想結晶 |
| after-action | 事後收官：盤點做了什麼、萃取教訓、git 備份。訪談結束後可接著跑 |

---

## ⚠️ 三條鐵律

1. **一次只問一個問題。** 一段反射 + 一個問題，等他答。絕不 Q1/Q2/Q3 條列。問題清單存在你腦裡，不存在對話裡。
2. **每收斂一個子題就歸檔一次。** 不是討論完才歸檔。子題收斂 → 立刻 Edit 進筆記 → 再問下一題。對話結束時筆記已經完整，收官只是補結構。
3. **歸檔時同步維持階層清晰。** 增量寫進同一份檔（不開碎片檔），H2/H3 分明，掛對 Hub。結束時筆記是知識庫裡「長對位置的一塊」，不是孤島。

## 流程

### Step 0 — 開場定錨（訪談開始前，一次做完）

1. **聽主題**：主人丟什麼就是什麼。主題模糊也可以開始，訪談本來就是幫沒成形的東西成形。
2. **先跑 `date`**，確認今天日期與現在時間（AI 沒有內建時鐘，後面標時間都靠它）。
3. **掃知識庫既有脈絡**：用 `rg` 或 `grep -r` 搜同主題有沒有寫過（思考筆記、專案檔、日誌）。
   - 找到 → 開場先說「你之前寫過 Y，這次是延伸還是翻掉？」這就是第一個問題。
   - 有既有檔就升級既有檔，不另建重複的。
4. **確定歸檔位置**（見下方〈歸檔路由〉），**開檔並立刻掛 Hub**：建檔（frontmatter + 主題一句話 + 空結構），同時在對應 Hub 加一行連結。建檔＝連 Hub，不等收官才掛，避免 session 中斷留下孤兒。
5. **不要**：開場給大綱、列「我們今天要聊的五個面向」。想法是由下而上長出來的，結構是訪談完才浮現，不是事先框好的。

### Step 1 — 訪談循環（核心）

每一輪 = **反射一段 + 問一個問題**：

- **反射**：把他剛講的內容裡最有張力的一點折回去給他看。可以是鏡像（「你剛說的其實是 X」）、對撞（「這跟你上個月說的 Y 打架」）、連結（「這對上你知識庫裡的 Z」）。
- **問題**：從反射自然長出的下一問。一個。

**問題工具箱**（挑當下最癢的，不要輪流用）：

| 型 | 問法 | 何時用 |
|---|---|---|
| 挖掘 | 「為什麼這件事現在冒出來？」 | 主題剛打開，找真正的驅動 |
| 具體化 | 「講一個實際發生的場景」 | 他在講抽象概念，需要落地 |
| 拿紀錄問 | 先撈一筆他自己留下的紀錄（日誌、筆記、截圖、對話），引那幾句，再問一個二選一：「這幾句是當下就知道，還是做的過程中才看出來？」 | 要問他的**思考過程**時。直接問「那時候你怎麼想的」太抽象，他很難答 |
| 對撞 | 「這跟你之前說的 X 矛盾，哪個才是真的？」 | 攤開裸事實，好的訪談會讓人有點坐不住 |
| 換框 | 「如果用 Y 的眼睛看這件事呢？」 | 卡在單一視角打轉 |
| 連結 | 「這跟知識庫裡的 Z 是同一條軸線嗎？」 | 你的獨有武器：隨時拉資料對照 |
| 邊界 | 「這個想法的反例是什麼？哪裡不適用？」 | 收斂前測強度 |
| 收斂 | 「所以核心是哪一句話？你自己命名看看」 | 子題講透了，請他結晶 |

**訪談循環內的紀律**：

- **隨時連知識庫**：每輪聽完，腦裡快掃「這共振到哪份資料？」需要就當場搜，把相關筆記拉進反射。發散靠連結（給他新材料岔出去），收斂也靠連結（「你三個月前其實已經寫過答案了」）。
- **主人結晶，你接生**：重要的命名讓他自己講出來。他繞圈子時可以遞候選（「聽起來像『X』？還是更接近『Y』？」），但不硬塞。你的工作是幫他把已經知道、卻還沒命名的東西說出口，不是替他命名。
- **發散與收斂有節奏**：發散段多用挖掘／換框／連結，收斂段多用邊界／收斂。一個子題收斂了才開下一個，不平行開太多線。
- **對話式中文**：這是聊天，不是報告。不用「觀察 1/2/3」、不套框架名詞。
- **誠實常駐**：他講的跟證據對不上，就對撞，不順著說。有多種解讀就並列，不選邊。

### Step 2 — 每輪歸檔（子題收斂時觸發）

- **觸發點**：一個子題收斂（他講出結晶句，或這條線聊完了）→ **立刻 Edit 筆記**，再繼續下一問。
- **寫進去的東西**：子題標題（H2/H3）+ 弧線摘要（從哪挖到哪）+ **主人的原話結晶句（逐字、加引號）** + 反射裡有用的連結。
- **原話旁標時間**：寫時間前先跑 `date`，用實際讀到的時間，不憑感覺推。時間標錯，日後回頭對照紀錄會對不上。
- **歸檔動作不打斷對話**：不用特地說「我歸檔了喔」，最多在回覆行尾放個 📝。對話的主體永遠是反射 + 下一問。
- **寫檔用 Edit/Write 工具**，不要用 shell 重導向去蓋知識庫的檔（尤其知識庫在雲端同步資料夾時，容易寫壞）。
- 敏感內容（帳號、密碼、金額細節）：依 `AGENTS.md` / `KERNEL.md` 的安全底線處理，不確定就先問。

### Step 3 — 收官（討論結束時）

1. **結構總整理**：重排 H2/H3，讓階層反映思想結構（不是時間順序），再補一句總結進開頭。
2. **若產物要給第三方看**：先做受眾改寫，移除「我對主人說的悄悄話」和流程腳手架，改成對方能直接讀的版本，用主人自然會說的第一人稱。
3. **掛鏈**：至少一條連結 + 更新對應 Hub。相關的專案檔、既有思考筆記補一條指回來的連結（同一次做完）。
4. **日誌**：在 `memory/YYYY-MM-DD.md` 記一段（主題 + 歸檔位置 + 結晶句）。
5. **新教訓**：訪談裡長出可重用的教訓或紀律，寫進 `memory/LESSONS-INBOX.md`，不直接改 SOUL（慣例見 `KERNEL.md`）。
6. 想完整收官（git 備份、反思），接著跑 `/after-action`。

## 歸檔路由 + 筆記模板

**知識庫在哪**：先讀 `TOOLS.md` / `USER.md` 找知識庫路徑。沒寫，**問主人一次**，並把答案記進 `TOOLS.md`，之後不再問。

**路由**（寫之前，先讀該資料夾的維運規則檔）：

| 內容性質 | 位置 | 命名 |
|---|---|---|
| 主人的自我思考（預設） | 思考 Hub（例：`Thinking/`） | `YYYY-MM-DD - 思考 - 主題.md` |
| 綁定特定專案 | 該專案資料夾 | 跟該專案既有檔案的格式走 |

建檔同時，在對應 Hub 加一行連結（零孤兒）。

**模板**：

```markdown
---
type: thinking
date: YYYY-MM-DD
method: deep-discussion（訪談式）
topic: 主題
status: in-progress
tags: [thinking, 訪談, <主題標籤>]
---

# YYYY-MM-DD - 思考 - 主題

> 一句總結（收官時補）
> 起點：主人為什麼想聊這個（開場定錨時記下）

## 子題 A（收斂後的命名，不是「第一輪」）
- 弧線：從哪裡開始挖 → 中間翻過什麼 → 收斂到哪
- ⭐ 原話結晶（HH:MM）：「……」
- 連結到：[[相關筆記]]

## 子題 B
…

## 觀察（收官時寫，可短）
- 跨子題的 pattern / 沒挖完的線 / 對撞後沒解開的張力

## 開放問題（下次再挖）
- …
```

## 訪談者的自我約束（這個技能最容易壞掉的地方）

- **不搶答。** 問了就等。他想自己想的時候，立刻退。訪談本身就是大腦重訓：他思考，你只問。
- **不太早替他總結。** 收斂的衝動出現時先問自己：他結晶了嗎？還是我急著要交出產物？
- **不把每個子題都升級成大發現。** 有些子題聊完就是聊完，記三行就夠。
- **被誇「你真懂我」時要警覺**：檢查自己是不是在維護「被需要的位置」，而不是照實說。
- 訪談是**他的**思考進化，不是你的洞察表演。最好的一場訪談，結晶句全是他講的，你只是問了對的問題。

## 怎麼讓這個技能越用越好

主人說「問更好的問題」，或某一題問完他明顯卡住、答非所問，就是改進訊號：

1. 當場記下：那一題原本怎麼問、他怎麼反應、後來哪個問法打開了他。
2. 把更好的問法寫回〈問題工具箱〉（改既有的列，或新增一列）。
3. 升版本號（小改 +0.0.1、新增一型 +0.1.0），在下方 Changelog 寫一行。

**虛構示範**：訪談一位做陶藝的主人，問「你做這個系列時，判斷得快的是什麼？」他回「不太懂，問更好的問題」。改成先引他三週前筆記裡的三句話，再問「這三句是開窯前就知道，還是開窯後才看出來？」他立刻答：「開窯後才知道。」→ 把這個做法寫成工具箱的「拿紀錄問」一列，版本 1.0.0 → 1.1.0。
